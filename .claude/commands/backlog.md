---
description: Synchronise les développements en cours avec les issues GitHub (label pending-dev)
---

Tu tiens à jour le backlog du repo `clmntlts/stravacallback` sous forme d'issues
GitHub, via le serveur MCP GitHub (`mcp__github__*`). Objectif : **tout
développement en cours / différé / "à faire" est reflété par une issue ouverte
avec le label `pending-dev`**.

Argument optionnel : $ARGUMENTS (ex. un item précis à déposer). Sinon, fais une
synchronisation complète.

Procédure :

1. `mcp__github__list_issues` (owner `clmntlts`, repo `stravacallback`,
   labels `["pending-dev"]`, state `OPEN`) pour connaître l'existant.
2. Recense les développements en cours/différés du moment : items non traités
   d'une revue, TODO du code, prérequis, améliorations repérées, et tout ce que
   `$ARGUMENTS` précise.
3. Pour chaque item :
   - S'il **existe déjà** une issue `pending-dev` équivalente → la mettre à jour
     (`method: "update"`) si besoin, ne pas dupliquer.
   - Sinon → `mcp__github__issue_write` (`method: "create"`) avec un titre clair,
     un corps { contexte, à faire (cases à cocher), fichiers concernés }, et les
     labels `pending-dev` + une catégorie (`training` | `code` | `infra` | `research`).
   - Termine chaque corps par la ligne d'attribution :
     `\n---\n_Generated by [Claude Code](https://claude.ai/code)_`
4. **Fermeture** : si un développement listé est désormais livré, fermer l'issue
   correspondante (`method: "update"`, `state: "closed"`, `state_reason:
   "completed"`) en référençant le commit/PR.
5. Terminer par un récap : issues créées / mises à jour / fermées, avec leurs URLs.

Ne crée jamais de doublon ; en cas de doute, mets à jour l'issue la plus proche.
